# 모바일 화면 점검표

원칙 출처와 신뢰도는 지식 노트 7f751e05(모바일 UX 철칙 목록)에 있다. 수치는 2차 자료 인용이며 원전 미확인.
**자동 검사**(tests/test_css_rules.py)는 CSS 숫자 규칙을, **눈 검사**는 화면을 보고 확인한다.

## 자동 검사 (CSS가 깨뜨리면 테스트 실패)
- 터치 타깃 토큰 ≥ 48px, 타깃 간격 ≥ 8px
- 입력창 글자 ≥ 16px (iOS 확대 방지)
- 버튼·입력·탭·접기 요약·뒤로 버튼에 최소 높이 토큰 적용, 목록 행·체크 행 ≥ 56px
- 텍스트·상태 색 대비 ≥ 4.5:1 (라이트·다크 모두, 배경·표면 모두)
- safe-area 인셋, `prefers-reduced-motion` 존재
- 렌더: viewport-fit=cover, 확대 막지 않음(`user-scalable` 없음), 배지 글자에 의미 포함

## 눈 검사 (화면마다)
1. 한 화면에 질문/목표가 하나인가. 주요 동작은 화면 아래 엄지 닿는 곳(`mf-actionbar`)에 있는가.
2. 320px 폭에서 가로 스크롤이 없는가. 글자 크기를 키워도 깨지지 않는가.
3. 줄 전체가 탭 영역인가(체크박스만 작지 않은가). 인접 타깃이 8px 이상 떨어져 있는가.
4. 입력은 최소인가. 알맞은 `type`/`inputmode`/`autocomplete`를 줬는가. 라벨은 입력 위, 오류는 입력 아래에 있는가.
5. 색만으로 의미를 전달하지 않았는가(배지에 글자·아이콘). 오류는 `role="alert"`.
6. 대기가 긴 작업은 진행 표시/스켈레톤이 있고 화면을 닫아도 이어지는가.
7. 키보드가 올라와도 주요 버튼이 가려지지 않는가(실기기 확인 필요, 미검증).
8. 제스처에만 의존하지 않는가(스와이프 같은 동작은 버튼 대안 필수).
