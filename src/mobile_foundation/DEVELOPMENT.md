# 공통 모바일 화면을 유지하며 기능 추가하기

화면마다 같은 CSS와 상태 처리를 다시 만들지 않도록 기존 프레임·매크로·토큰에서 시작합니다. 이 안내는 설치된 패키지의 `python -m mobile_foundation.guide`로도 읽을 수 있습니다.

## 재사용 지도

| 만들 화면/동작 | 먼저 사용할 구성 | 앱에서 정할 내용 |
|---|---|---|
| 최상위 목록·탐색 | mf/frame_tabs.html, tabbar | 탭 목적·경로·현재 탭 |
| 상세·편집 | mf/frame_detail.html, topbar, actionbar | 뒤로 가기·주요 동작·업무 입력 |
| 폼·오류 | field, button, notice | 값·업무 검증·오류 메시지 |
| 목록·비어 있음·로딩 | row, empty, skeleton_lines, progress | 데이터·상태 전환·재시도 |
| 색·간격·글꼴·터치 영역 | mf 토큰과 기존 CSS 클래스 | 앱 브랜드 토큰 재정의 |

매크로는 mf/macros.html, 프레임·갤러리는 mf 템플릿 경로에 있습니다. Python에서는 mobile_foundation.TEMPLATE_DIR / STATIC_DIR로 찾습니다. 공개 매크로 인자는 설치된 소스를 읽어 확인합니다. React 컴포넌트를 제공한다고 가정하지 않습니다.

## 매 화면 변경 순서

1. 목록→선택→상세→동작의 사용자 흐름과 이번에 바꿀 한 화면을 정합니다.
2. 정상·빈 결과·로딩·오류·비활성 중 해당 상태와 빠져나갈 다음 행동을 정합니다. 기존 프레임/매크로와 소비 앱에서 유사 화면을 찾아 재사용합니다.
3. 업무 데이터·경로·문구는 앱에 둡니다. 여러 앱에 필요한 표시/접근성/레이아웃 결함은 Foundation에서 수정하고 패키지를 갱신합니다. 앱에서 mf-*를 같은 이름으로 재구현하지 않습니다. 앱 고유 클래스는 다른 접두사를 사용합니다.
4. 최소 화면을 렌더하고 DOM을 검사한 뒤 작은 폭·긴 글자·키보드·실제 입력을 확인합니다. 기반 CSS 전체 덮어쓰기보다 토큰·공개 매크로 인자로 해결합니다. DOM에 업무 규칙과 네트워크 조립을 섞지 않습니다.
5. 변경한 범위의 중복 CSS·인라인 스타일·미사용 상태를 정리하고 관련 렌더 회귀 검사를 남깁니다. 실제로 반복되는 구성만 상위 프레임/매크로로 추출합니다.

소비 앱 AGENTS.md에는 이 안내를 읽는 명령과 실제 앱의 렌더·테스트 명령을 짧게 연결합니다. 작은 수정은 작업 설명에 판단을 남기고, 공개 매크로·토큰 계약을 바꾸면 원본 Foundation 설계를 먼저 갱신합니다. 긴 양식이나 추가 사용자 승인 절차는 필요하지 않습니다.

## 완료 증거

렌더된 전체 페이지를 저장한 뒤 실행합니다.

```sh
python -m mobile_foundation.quality rendered-page.html
```

이 검사는 mf 클래스·ID·라벨/오류 연결·탭·하단 여백 계약을 확인합니다. 실제 클릭·스크롤·화면 잘림·접근성 전체·미적 품질은 브라우저/기기에서 확인합니다. 원본 저장소 자체 변경은 `bash scripts/check-quality.sh`로 검사합니다.

완료 보고에는 사용한 프레임/매크로, 새 구성의 소유 위치, 검사한 상태·화면 폭·명령과 결과, 브라우저/실기기 미확인 범위를 남깁니다. 기존 이슈·PR·설계 문서를 사용하며 다른 개인 기억의 복사본을 만들지 않습니다.

## 배포 점검·앱 중단

앱이 중단된 동안의 안내는 앱 외부 프록시에서 제공합니다. 공통 도구는 `python -m mobile_foundation.maintenance`이며 `export`, `mode on/off`, `verify`를 제공합니다. 생성된 설정의 진입점으로 트래픽을 연결해야 동작합니다. 이미 열린 웹 화면에는 공통 `createAvailability`를 fetch 경계에서 조합하고 기존 입력·게임 상태를 유지합니다. 앱의 쓰기 요청을 자동 재전송하지 않습니다. 배포 도구와 같은 위치의 README에서 Nginx 연결·API JSON 보존·검사 명령을 확인하세요.
